# Проект "AskPupkin" — Сервис вопросов и ответов

Учебный проект в рамках курса VK Education "Web-технологии". Это полнофункциональный клон Stack Overflow, реализованный на Django. Сервис позволяет пользователям задавать вопросы, получать ответы, голосовать за лучший контент и формировать сообщество.

## Технологии 
*   **Backend:** Python 3.12+, Django 5.1+
*   **Web-Server & Proxy:** **Nginx** (раздача статики, проксирование, кэширование, Gzip)
*   **WSGI Server:** **Gunicorn**
*   **Database:** PostgreSQL 15+ (запущена в изолированном Docker-контейнере)
*   **Верстка:** HTML5, CSS3, Bootstrap 5.3 (локальное подключение статики)
*   **Контейнеризация:** Docker, Docker Compose
*   **Инструменты отладки:** Django Debug Toolbar (мониторинг SQL-запросов и N+1)
*   **Генерация данных:** Faker (наполнение базы миллионами записей)
*   **Frontend Logic:** jQuery 3.7.1
*   **Очереди задач:** Celery + Celery Beat
*   **Брокер и Кэш:** Redis (разделение по БД: 0 — кэш, 1 — брокер, 2 — расписание)
*   **Real-time:** Centrifugo (WebSockets)
*   **Email:** Maildev (локальный SMTP-сервер)
*   **Поиск:** Full-text search (FTS) PostgreSQL

## Работа с окружением и СУБД
В проекте реализована гибкая настройка через переменные окружения. Для корректной работы Docker Compose и устранения предупреждений о пустых переменных используется файл `.env.docker`.

*   `.env.example` — эталонный список переменных (хранится в Git).
*   `.env.docker` — файл с реальными настройками подключения к PostgreSQL (добавлен в `.gitignore`).

## Как запустить проект

### 1. Подготовка
Клонируйте репозиторий и создайте локальный файл настроек из шаблона:
```bash
git clone <ссылка_на_ваш_репозиторий>
cd 2026-VK-EDU-Web-11-Kontorzhevskiy-A
cp .env.example .env.docker
```
Убедитесь, что внутри .env.docker параметр DB_HOST установлен в значение db, а также содержит настройки для Redis и Centrifugo.

### 2. Запуск через Docker Compose
Для того чтобы Docker корректно подхватил настройки, используйте флаг
--env-file. Проект настроен на работу через связку **Nginx (порт 80) + Gunicorn (порт 8080)**.

Сборка и запуск всех сервисов (в фоновом режиме)
```bash
docker compose --env-file .env.docker up --build -d
```
Выполнение миграций (создание таблиц в PostgreSQL)
```bash
docker compose --env-file .env.docker exec web python manage.py migrate
```
**Сбор статики (необходимо для корректной работы Nginx):**
```bash
docker compose --env-file .env.docker exec web python manage.py collectstatic --noinput
```
Создание администратора (для входа в админ-панель /admin/)
```bash
docker compose --env-file .env.docker exec web python manage.py createsuperuser
```

### 3. Наполнение базы тестовыми данными
Для генерации "рыбы" используется кастомная команда fill_db. Она поддерживает
bulk_create для обеспечения высокой скорости вставки данных.

Формат: python manage.py fill_db <ratio>
Пример для создания 100 пользователей, 1000 вопросов и 10 000 ответов:
```bash
docker compose --env-file .env.docker exec web python manage.py fill_db 100
```

### 4. Запуск простого WSGI-скрипта
Для проверки работы WSGI-протокола вне Django (на порту 8081):
```bash
docker compose exec web gunicorn simple_wsgi:application -b 0.0.0.0:8081
```

## Оптимизация и контроль качества
  - **Nginx Caching & Gzip:** Веб-сервер настроен на сжатие контента (gzip), кэширование статики в браузере (`expires 30d`) и серверное кэширование динамических ответов (`proxy_cache`).
  - **N+1 Query Detection:** В проекте настроен Django Debug Toolbar. Если
    DEBUG=True, справа отображается панель, где можно проверить количество
    SQL-запросов. Все выборки оптимизированы с помощью select_related и
    prefetch_related.
  - **Обработка 404:** При попытке доступа к несуществующему вопросу или тегу
    приложение возвращает кастомную страницу 404.html.
  - **Состояние пустоты:** Для всех списков проработаны сценарии {% empty %} на
    случай отсутствия данных в БД.
  - **Работа с Media:** Загруженные файлы (аватары) раздаются через Nginx из директории `/uploads/`.

## Сравнение производительности
В ходе настройки инфраструктуры проведено нагрузочное тестирование (Nginx vs Gunicorn). Результаты измерений утилитой `ab` и ответы на вопросы по производительности находятся в отдельном файле **load_testing_results.md**

## Ключевой функционал
* Авторизация: Полноценный цикл Login/Signup/Logout. При выходе пользователь остается на текущей странице.
* Профиль: Возможность смены ника и аватара. 
* Контент: Добавление вопросов (до 3 тегов через запятую) и ответов (с автоматическим скроллом к новому ответу через якорь #answer-id).
* UX/UI: Возможность писать ответы заблокирована и снабжена всплывающей подсказкой.
* Оптимизация: Использование select_related и prefetch_related для исключения проблем N+1 запросов.
* Ошибки: Кастомная страница 404.html и обработка "пустых" состояний списков через {% empty %}.
* Профиль: Смена ника и аватара. Реализована валидация файлов (размер до 2МБ, форматы изображений) и генерация неперебираемых имен файлов через UUID.
* AJAX-интерактив: Система лайков/дизлайков для вопросов и ответов, а также выбор правильного ответа автором вопроса реализованы без перезагрузки страницы.
* Безопасность AJAX: Настроена автоматическая подстановка CSRF-токена в заголовки запросов jQuery.

## Список основных маршрутов (Namespaces)

| Страница               | URL                  | Имя маршрута                 |
| :--------------------- | :------------------- | :--------------------------- |
| **Главная (Новые)**    | `/`                  | `questions:index`            |
| **Популярные вопросы** | `/hot/`              | `questions:hot_questions`    |
| **Список по тегу**     | `/tag/<name>/`       | `questions:tag`              |
| **Страница вопроса**   | `/question/<id>/`    | `questions:question`         |
| **Задать вопрос**      | `/ask/`              | `questions:ask`              |
| **Вход / Регистрация** | `/accounts/...`      | `core:login` / `core:signup` |
| **Настройки профиля**  | `/accounts/profile/` | `core:profile`               |
| **Лайк/Дизлайк**       | `/vote/`             | `questions:vote`             |
| **Правильный ответ**   | `/mark_correct/`     | `questions:mark_correct`     |
| **Проверка WSGI**      | `:8081/`             | (simple_wsgi)                |

## Структура проекта

  - `application/` — Настройки проекта (settings.py, urls.py).
  - `nginx.conf` — Конфигурация Nginx (proxy, static, cache).
  - `gunicorn.conf.py` — Конфигурация воркеров Gunicorn.
  - `simple_wsgi.py` — Простой WSGI-скрипт.
  - `core/` — Приложение для работы с пользователями (модель Profile).
  - `questions/` — Основное приложение (модели, менеджеры, логика контента).
  - `templates/` — Наследование шаблонов и компоненты интерфейса.
  - `static/` — Локальная статика (Bootstrap, CSS, JS).
  - `media/` — Хранилище загружаемых аватарок.
